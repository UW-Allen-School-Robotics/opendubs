# Content split before going public: inventory and proposal

Owned by the Hygiene lane, with the Choreography lane for show content (its list is folded in below).
The inventory was taken against `main` at `0857919` on 2026-10-24. **Status updated 2026-11-03**
against `main` at `8d2104ae` (see "Where it stands"): the engine changes are merged, and the
private `opendubs-shows` repository holds copies of most of the content. The originals are still on
`main` until each owner removes them.

**The requirement (the maintainers, 2026-10-22).** Holiday- and show-specific material is a use
case, not core, and moves out before the repo goes public. Core keeps the engine, the generic
effector interface and one or two tiny example shows.

**Default destination.** A separate `opendubs-shows` content repository, loaded from a configured
folder. The studio already defaults to `~/opendubs-shows` and `~/opendubs-library`. "Core
example" means the item stays here as a small, generic example.

**History.** The maintainers accept that names stay in git history. Only media and third-party
content would matter, and this sweep found none in any branch or PR head:

- no audio, video, lyrics or stage art has ever been committed;
- the Surge vendor URDF and meshes were never committed;
- song titles appear only in commit messages, and as worked examples in a few design notes and one
  docstring (row 14);
- the only images in the show paths are the composer guide's screenshots
  (`docs/assets/composer/composer-0[1-8]-*.png`), generated by `doc_shots.py` from `wave-and-nod`
  with generated music.

Moving an item therefore needs no history rewrite.

## The engine changes the moves depend on

Each one is small, and each belongs to its owner. Choreography's smallest set is (a)–(d). Changes
1, 2, 3, 4 and 6 are merged; change 5 is open (see "Where it stands").

1. **(a) Shows folder.** A setting for the composer's built-in shows folder, so it can point at the
   content folder. The repo keeps just `hello`, `beat-demo` and `wave-and-nod` (the maintainers'
   choice). Choreography owns this.
2. **(b) Discovery.** A theme and skin manifest replaces the hard-coded names. These are
   `cue.py` `FACE_THEMES` and `CODE_SKINS`, `library.py` `CODE_SKIN_NAMES`,
   `head_protocol.py` `THEMES_BUILT_IN` and `vocab.js`. Core keeps `plain`/`none` and
   `default`/`ring`. Choreography owns the validator; Face & HRI owns the face's skin list. The
   protocol part needs the Tablet lane's agreement.
3. **Code skins load from the content folder.** Face & HRI owns this. The library's `skin`
   kind and `skins/asset.js` are the precedent.
4. **(c) Effectors search path.** The repo's `effectors/` plus the content folder's, with drivers
   loaded by name. Choreography owns this.
5. **(d) A neutral stage tempo.** The stage page's default bpm. Choreography owns this.
6. **Tests use fixtures** under `tests/` (or the three kept shows), so CI never depends on the
   content repo. Each lane does this for its own tests.
