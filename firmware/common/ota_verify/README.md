# ota_verify: the signed-update check every OpenDubs board runs

Every OpenDubs board that updates itself over the network (the StamPLC, and the neck Dial) installs
only an image signed on the Thor, for that board. This library is the one check they all run, before
an image may become bootable. Design and reasoning: [notes/design/firmware-signing.md](../../../notes/design/firmware-signing.md).
Keys and signing on the Thor: [software/stack/firmware-signing/](../../../software/stack/firmware-signing/README.md).

| file | what |
|---|---|
| `src/ota_verify.h`, `src/ota_verify.cpp` | the check: plain mbedTLS (2.28 and 3.x alike), no Arduino |
| `src/ota_keys.h` | GENERATED from `keys/*.der` by `tools/ota_keys.py`: the keys every build trusts |
| `src/ota_selftest.h` | GENERATED by `tools/make_selftest.sh`: the known-answer vector for the boot self-test |
| `keys/` | the project's firmware-signing **public** keys, `<key id>.der`. One normally; two during a rotation |
| `tests/test_ota_verify.sh` | the host test: builds the check against mbedTLS on a laptop and signs with the Thor's own script |

## What is signed

ECDSA P-256 over SHA-256 of `"OPENDUBS-FW-SIG-1" \0 <board> \0 <image>`. The signature is detached, in
DER, at most `OTA_SIG_MAX` bytes, and served as `<image URL>.sig`. Because the board name is inside
the signature, an image signed for one board fails on another. That matters: the StamPLC and the Dial
are both ESP32-S3s, so a StamPLC image would otherwise boot on the Dial and break its updates until
someone fits a USB cable. Board names:
`stamplc`, `neck`.

## Linking it into a firmware

A PlatformIO project links the library with a relative symlink, `lib/ota_verify -> ../../common/ota_verify`.
It resolves both in the repository and in the robot's flat `/opt/opendubs` layout, where `deploy-all.sh`
ships this folder as `/opt/opendubs/common`. It needs no `platformio.ini` change: PlatformIO builds
whatever is in `lib/`.

## What a board must do (the interface)

```cpp
#include "ota_verify.h"
#include "ota_keys.h"            // OTA_KEYS, OTA_KEY_COUNT

// in setup(), once, before any time-critical loop (three ECDSA verifies: tens of ms):
ota_selftest_ok = otaVerifySelfTest();

// on `OTA <url>`:
// 1. GET <url>.sig into a buffer of OTA_SIG_MAX bytes. Missing or too long: reject.
// 2. GET <url>; Update.begin(len); OtaVerify v; otaVerifyBegin(v, "<board>");
//    for each chunk: Update.write(chunk) and otaVerifyUpdate(v, chunk).
//    On any abort: Update.abort() and otaVerifyAbort(v).
// 3. int which; OtaVerifyResult r = otaVerifyFinish(v, sig, sig_len, OTA_KEYS, OTA_KEY_COUNT, &which);
// 4. Not OTA_SIG_OK and enforcing: Update.abort(), report otaVerifyReason(r), keep running. The new
//    slot is never selected; the running app is untouched and still the one that boots.
// 5. Otherwise Update.end(true), report the key (otaKeyId(OTA_KEYS[which], ...)), reboot.
// Report, in the board's status (PING or telemetry): the trusted key ids, and whether the self-test passed.
```

**The verdict must come before `Update.end(true)`.** That call is what makes the new image bootable.
`Update.writeStream()` can't be used as-is, because the bytes have to pass through the hash. Write the
chunks yourself.

## Policy: how a board treats a failed check

| | StamPLC | neck Dial |
|---|---|---|
| recovery if updates break | USB, on the robot | USB, with a cable fitted for the visit (the Dial normally runs without one) |
| bad signature, enforcing | reject, keep running | reject, keep running |
| no trusted key in the build | rejects everything | **must not build**: `static_assert(OTA_KEY_COUNT > 0)` unless report-only |
| self-test FAILED (the check is broken on this board) | rejects everything | **report-only**: installs anyway and reports `otaverify=BROKEN` loudly. A verify bug must never cost a cable visit |
| report-only build (`-DOTA_SIG_REPORT_ONLY`) | not used | the bootstrap build only: checks, reports, installs anyway |

Nobody else can trigger report-only behaviour. It comes either from the build (the report-only flag)
or from this build's own self-test failing, which is deterministic code, not input. The Dial's
bootstrap sequence is in the design note: a report-only image first, a signed round trip proved on
that unit, then the enforcing image.

## Keys

`keys/` holds public keys only: the private key never leaves the Thor. To trust a key, add
`<id>.der` and run `python3 tools/ota_keys.py`. CI and reviewers use `--check`. A board trusts every
key in its build. Keep two only during a rotation: current and next, so an update signed with either
installs. Procedures: `software/stack/firmware-signing/README.md`.
